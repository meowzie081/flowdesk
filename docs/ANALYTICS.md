# Google Analytics 4

## Что измеряем

Цель: понять, какие разделы использует команда и какие действия завершает. Данные о содержимом работы в GA4 не отправляем.

| Событие | Когда отправляется | Допустимые параметры |
|---|---|---|
| `page_view` | Открытие раздела и переход между разделами | Синтетический адрес раздела, фиксированный заголовок |
| `task_created` | Успешное создание на канбане | `source=board` |
| `task_moved` | Успешное перемещение на канбане | `source=board` |
| `task_archived` | Успешное архивирование на канбане | `source=board` |
| `message_sent` | Успешная отправка обычного сообщения | `source=chat` |
| `file_uploaded` | Файл прикреплён к сохранённой задаче/сообщению | `source=task/chat`, `kind=image/pdf/other` |
| `ai_response_received` | API вернул успешный ответ AI | Фиксированная команда, источник при наличии |
| `search_used` | Успешный запрос первой страницы поиска после debounce | `source=search` |

События не являются финансовым учётом или точным числом объектов в БД: отказ от аналитики, блокировщики, другие способы создания карточек и повторные запросы влияют на полноту. `ai_response_received` фиксирует получение ответа, а не качество текста или создание предложенной карточки.

## Подключение

1. В Google Analytics создайте ресурс GA4 и веб-поток для действительного HTTPS-адреса приложения.
2. Скопируйте Measurement ID вида `G-XXXXXXXXXX` в `NEXT_PUBLIC_GA_ID` файла `.env` на сервере.
3. В настройках веб-потока отключите **Enhanced measurement** целиком. Интеграция отправляет события вручную. Автоматические измерения могут дублировать просмотры, передавать исходные URL и собирать ненужные события.
4. Не подключайте второй Google tag через Tag Manager или HTML: это создаст дубли.
5. Пересоберите: `docker compose up -d --build`. Это публичная переменная сборки, простого перезапуска контейнера недостаточно.
6. Откройте приложение и нажмите «Разрешить аналитику». В GA4 откройте Realtime, переключите раздел и создайте тестовую задачу.
7. При необходимости добавьте пользовательские определения для `source`, `kind`, `command`. Их появление в обычных отчётах может требовать обработки данных Google.

Пустой или некорректный ID отключает компонент. Никакого действительного ресурса GA4 или аккаунта эта поставка не создаёт.

## Приватность и управление

- До разрешения не загружается `gtag.js` и не отправляются события.
- Выбор хранится в браузере. «Настройки аналитики» внизу страницы позволяет его изменить; изменение синхронизируется между вкладками.
- При отказе включается `ga-disable-ID`, дальнейшие события блокируются. Ранее собранные данные и существующие cookies Google автоматически не удаляются.
- `/d/<uuid>/board?task=<uuid>` преобразуется в `/app/board`. Query, hash, UUID, email, поисковый запрос, имена файлов и пользовательские заголовки не входят в отправляемые параметры.
- Обёртка отбрасывает неизвестные имена событий, ключи параметров и значения вне разрешённых списков.
- Google получает обычные технические данные сетевого запроса и применяет собственные механизмы измерения. Отсутствие текстов задач не означает полную анонимность.

## Проверка

- До согласия: в Network нет запроса `googletagmanager.com/gtag/js`.
- После согласия: один tag, один ручной `page_view` на переход раздела. В настройках GA4 Enhanced measurement должен быть выключен.
- `dl`/page_location содержит только origin и синтетический путь.
- Неудачное сохранение задачи не создаёт `task_created`.
- После «Без аналитики» последующие действия не вызывают отправку через обёртку.

Локальные unit/UI-проверки используют подмену Google tag. Проверить реальное поступление в GA4 можно только после задания Measurement ID и согласия пользователя.
