# Email, Web Push и обучение

## Что добавлено

- Профиль → **Уведомления**: отдельное согласие на письма о событиях, объявления отдела и push на устройствах. По умолчанию внешние каналы выключены.
- **Объявления** в боковом меню: владелец пишет текст, проверяет предпросмотр и ставит рассылку в очередь. Участники читают объявления внутри отдела. Не более одной новой рассылки отдела в минуту; до 500 активных участников.
- Колокольчик: ссылки на объявления и настройки каналов.
- Web Push для поддерживаемых браузеров/PWA: разрешение запрашивается только после нажатия **«Подключить это устройство»**. Не более пяти устройств на аккаунт. В Telegram Mini App и Electron эта функция не предлагается; используйте браузер или внутренний колокольчик.
- Обучение при первом открытии главной страницы/отдела: пять коротких визуальных шагов, **«Пропустить»**, клавиша Escape, кнопки назад/далее. Завершение и пропуск сохраняются в аккаунте. Профиль → **«Пройти обучение снова»**. Если сохранение недоступно, доступно явное закрытие только на текущем устройстве.

## Обновление приложения

1. Сохраните свои `.env` и `.git`; обновите исходники из архива.
2. В Supabase SQL Editor выполните `supabase/migrations/0014_delivery_onboarding.sql` **один раз**, после миграций 0001–0013. Не запускайте заново весь каталог.
3. `npm ci`, `npm run typecheck`, `npm test`, `npm run test:db`, `npm run build`.
4. Опубликуйте код через свой GitHub/Vercel. Обучение и объявления внутри приложения работают уже после миграции и деплоя; внешняя доставка требует настройки ниже.

## Email через Resend

1. Создайте аккаунт на https://resend.com, подтвердите собственный домен отправителя по DNS в разделе Domains и получите API Key с правом отправки.
2. В Vercel → Settings → Environment Variables → **Production** (или на сервере в `.env`) задайте:

```env
RESEND_API_KEY=ваш_ключ
EMAIL_FROM=FlowDesk <notifications@ваш-домен.ru>
FLOWDESK_PUBLIC_URL=https://flowdesk-alpha-teal.vercel.app
SUPABASE_SERVICE_ROLE_KEY=ваш_серверный_ключ
```

Домен в `EMAIL_FROM` должен быть подтверждён в Resend. Тестовый отправитель провайдера имеет ограничения получателей и не подходит для рассылки команде. Если собственного домена нет, объявления внутри приложения и Web Push доступны отдельно; email подключите после настройки домена.

3. После изменения серверных переменных сделайте Redeploy.
4. Пользователь с реальной подтверждённой почтой открывает профиль, включает нужные категории email и сохраняет настройки.

Email берётся из Supabase Auth, а не из поля формы рассылки. Аккаунты вида `login@users.flowdesk.invalid`, созданные администратором, не имеют настоящего почтового ящика: им доступны колокольчик и push. В этой версии отдельная контактная почта для такого логина не добавляется.

Письмо о событии содержит общий текст и ссылку в приложение. Письмо-объявление содержит тему и текст владельца отдела; HTML экранируется. Письма отправляются индивидуально: чужие адреса не раскрываются. В каждом письме есть ссылка **на настройки отключения** в профиле (требуется вход). Отписки без входа в один клик здесь нет; это рабочие объявления команды с явным согласием, а не инструмент рекламных кампаний.

## Web Push

В корне проекта выполните **один раз на своём компьютере**:

```bash
npm run notifications:keys
```

Сохраните полученные `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `NOTIFICATION_CRON_SECRET` в локальном `.env` и серверных переменных Vercel. `VAPID_SUBJECT` замените на настоящий контакт, например `mailto:admin@company.ru`. Не публикуйте вывод и не добавляйте `.env` в GitHub. Все имена без `NEXT_PUBLIC_`; браузеру API возвращает только открытый VAPID-ключ.

Не генерируйте новую пару при каждом деплое: старые подписки используют прежний открытый ключ. При смене ключей отключите и заново подключите устройства. После настройки — Redeploy.

В браузере откройте опубликованный FlowDesk по HTTPS → профиль → **«Подключить это устройство»**, разрешите уведомления. На iPhone/iPad требуется поддерживаемая установленная на экран «Домой» PWA. Системные настройки и режим «Не беспокоить» могут скрывать уведомления.

Push показывает только «Новое уведомление. Откройте приложение.» и открывает FlowDesk. Названия задач, сообщения и объявления не попадают на экран блокировки. Нажатие фокусирует открытую вкладку либо открывает главную страницу.

При смене аккаунта на общем компьютере сначала нажмите **«Отключить это устройство»**. Флажок **«Получать push на подключённых устройствах»** выключает доставку всему аккаунту; кнопка отключения удаляет подписку только текущего браузера. Если браузер запретил уведомления, разрешите их в настройках сайта. Подписка с другого аккаунта не перезаписывается: отключите её в прежнем аккаунте либо сбросьте разрешение и переподключите устройство.

## Запуск очереди доставки

Нужен периодический POST на `/api/notifications/dispatch` с заголовком `Authorization: Bearer <NOTIFICATION_CRON_SECRET>`. Обработчик не использует браузерную сессию и проверяет отдельный секрет. GET не запускает отправку.

Для первого запуска:

```bash
npm run notifications:dispatch -- --dry-run
# Следующая команда уже отправляет накопленные письма/push:
npm run notifications:dispatch
```

`--dry-run` проверяет только адрес/формат секрета, не соединение с сервером и не доступность Resend/Web Push.

### Vercel + Supabase Cron

1. В Supabase включите расширения **pg_cron** и **pg_net** через Database → Extensions. Если `cron` не существует, расширение pg_cron ещё не включено.
2. В Supabase Vault через интерфейс создайте секреты:
   - `flowdesk_notification_url`: `https://flowdesk-alpha-teal.vercel.app/api/notifications/dispatch`;
   - `flowdesk_notification_cron_secret`: то же значение, что `NOTIFICATION_CRON_SECRET` в Vercel.
3. Проверьте, что на Production-маршрут нет Vercel Deployment Protection/страницы входа хостинга, затем в SQL Editor выполните:

```sql
select cron.schedule(
  'flowdesk-notifications',
  '* * * * *',
  $$
  select net.http_post(
    url := (select decrypted_secret from vault.decrypted_secrets
            where name = 'flowdesk_notification_url'),
    headers := jsonb_build_object(
      'Content-Type', 'application/json',
      'Authorization', 'Bearer ' ||
        (select decrypted_secret from vault.decrypted_secrets
         where name = 'flowdesk_notification_cron_secret')
    ),
    body := '{}'::jsonb,
    timeout_milliseconds := 55000
  );
  $$
);
```

Cron повторов задач `run_due_recurring()` оставьте: это **отдельная** задача. При смене домена обновите адрес и `FLOWDESK_PUBLIC_URL`. При смене секрета синхронно обновите Vault и Vercel. Нельзя вызывать защищённый endpoint из обычной вкладки без заголовка.

### Docker / VPS

```bash
docker compose --profile notifications up -d --build
docker compose logs --tail=50 notifications
```

Профиль `notifications` запускает отдельный worker, обращающийся к `http://web:3000/api/notifications/dispatch` раз в минуту. Все ключи передаются через `.env`; публичные ссылки писем используют HTTPS-адрес `FLOWDESK_PUBLIC_URL`. Docker использует Node.js 22. На VPS без Docker: `npm run notifications:dispatch -- --loop` под своим supervisor/systemd. Одновременно достаточно одного способа планирования; блокировка очереди допускает перекрывающиеся запуски.

## Очередь и ограничения

- Триггер создаёт задания только для включённых каналов на момент события. Включение подписки не рассылает старые уведомления.
- Перед отправкой повторно проверяются членство/блокировка, согласие и подтверждение почты.
- По три задания за HTTP-вызов (email и push — отдельные задания); при Cron раз в минуту это три задания в минуту. Решение рассчитано на небольшую команду. Для больших объёмов нужен отдельный worker с большей пропускной способностью и проверкой квот провайдера.
- Захват очереди использует `FOR UPDATE SKIP LOCKED` и уникальный token; повторные конкурентные вызовы не захватывают одно задание. Lease — пять минут.
- До пяти попыток с задержкой; сообщения старше 22 часов пропускаются. Idempotency-Key Resend равен ID задания. Повторный клик по кнопке объявления использует прежний UUID и не создаёт вторую рассылку.
- Push может повторно прийти при частичном сбое устройств: одинаковый tag группирует уведомление, но абсолютная доставка «ровно один раз» не гарантируется.
- Подписки с ответом 404/410 удаляются. Произвольные клиентские URL для исходящих запросов запрещены; допускаются известные push-хосты Google, Mozilla, Apple и Microsoft.
- Владелец видит агрегированные счётчики очереди за 30 дней. «Принято сервисом» означает успешный ответ сервиса, а не прочтение письма или гарантированное отображение push.
- Прочтение в колокольчике не отменяет уже созданное задание. Отключение канала до обработки отменяет отправку, но не отзывает уже принятое провайдером письмо.
- Неверная конфигурация/постоянная ошибка приводит к `failed`; после исправления проверьте новый тестовый сценарий. Не перезапускайте старые отправки вслепую.
- Провайдерские ключи, тела ошибок и email не выводятся worker-ом в логи. В БД хранится короткий код ошибки, сами endpoints доступны только серверной роли.

## Приёмка без массовой рассылки

1. После деплоя войдите первым аккаунтом: проверьте обучение, «Пропустить», отсутствие повторного показа после входа на другом устройстве и повторный запуск из профиля.
2. У второго аккаунта включите email-объявления и подключите браузер к push. Системный запрос не должен появляться до нажатия кнопки.
3. Владельцем отдела создайте короткое тестовое объявление через предпросмотр. Проверьте колокольчик и раздел «Объявления» второго аккаунта.
4. Запустите обработчик/дождитесь Cron. Проверьте письмо, браузерный push и счётчики. Для двух каналов могут понадобиться разные запуски.
5. Отключите каналы и создайте новое объявление через минуту: оно должно остаться в приложении, без внешней доставки.
6. Участник и наблюдатель могут читать объявления, но не публиковать; чужой отдел не виден. Заблокированный до отправки получатель ничего не получает.

Реальная доставка требует ваших ключей/домена, HTTPS, разрешения браузера и работающего планировщика. Автоматические проверки используют моки транспортов и локальный PostgreSQL/PGlite; они не отправляют настоящие письма и push.

Официальная документация: [Resend](https://resend.com/docs/api-reference/emails/send-email), [idempotency](https://resend.com/docs/dashboard/emails/idempotency-keys), [web-push](https://github.com/web-push-libs/web-push), [Apple Web Push](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers), [Supabase Vault](https://supabase.com/docs/guides/database/vault), [pg_net](https://supabase.com/docs/guides/database/extensions/pg_net).
