# «Мой день» и запросы помощи

Маршрут: `/d/<departmentId>/my-day`. При выборе отдела приложение открывает этот раздел.

## Правила

Дневной план личный, действует на календарную дату устройства и не меняет дедлайн. Автоматическая часть «Сегодня» включает назначенные пользователю незавершённые и неархивные задачи со сроком не позже сегодняшнего дня. Ручное планирование доступно для других своих активных задач. Убрать из ручного плана просроченную задачу можно, но она останется в автоматической части до изменения срока или завершения.

«От меня ждут ответа» показывает открытые запросы помощи и до 30 последних непрочитанных упоминаний/ответов в чате. Это список поводов проверить обсуждение: приложение не определяет, является ли сообщение вопросом. Полный список уведомлений остаётся в колокольчике.

Активный запрос на задачу только один. Запросы не заменяют `blocked_reason` и не перемещают карточки между колонками.

Состояния:

- `open`: запрос ждёт ответа назначенного коллеги.
- `answered`: ответ получен, автор должен проверить результат.
- `resolved`: автор или владелец подтвердил продолжение работы.
- `cancelled`: автор или владелец отменил запрос.

Автором становится пользователь, отправивший запрос. Отвечает только назначенный активный участник с правом записи. Создание недоступно для завершённых и архивных задач. Прямые изменения запросов из браузера запрещены; переходы выполняют функции PostgreSQL с проверками доступа. Все участники отдела могут читать доступные им запросы в карточке, персональный экран выбирает относящиеся к пользователю, владелец также видит остальные ожидания команды. При удалении задачи её планы и запросы удаляются каскадно.

Последняя карточка хранится в localStorage отдельно для аккаунта и отдела. Перед показом приложение проверяет, что карточка по-прежнему доступна и не архивна. Отключённый localStorage не мешает другим функциям.

## Обновление существующей установки

1. Выполнить `supabase/migrations/0013_my_day.sql` в SQL Editor. Старые миграции повторно не запускать.
2. Обновить код из архива в своём репозитории, сохранив собственные `.env` и настройки.
3. Выполнить `npm ci` и `npm run typecheck && npm test && npm run test:db && npm run build`.
4. Отправить изменения в GitHub, дождаться сборки Vercel.
5. Проверить запрос помощи между двумя аккаунтами, ответ и продолжение работы.

Миграция не требует новых переменных окружения и не меняет Supabase Cron.
