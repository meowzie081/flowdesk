# Telegram Mini App FlowDesk

В Telegram открывается тот же FlowDesk: «Мой день», канбан, карточки, чат, файлы и остальные доступные пользователю разделы. Бот запускает приложение кнопкой и командами `/start`, `/app`, `/help` в личном чате. Данные остаются в существующем Supabase-проекте.

## Что уже есть в коде

- Публичная стартовая страница `/telegram` и подключение официального Telegram Web App SDK только для этого режима.
- Разворачивание окна, обработка безопасных отступов, темы Telegram и нативной кнопки «Назад».
- Вход по существующему логину/email и паролю FlowDesk. Сессия сохраняется в браузерном хранилище Telegram, отдельно от обычного браузера.
- Webhook `/api/telegram/webhook` с проверкой секретного заголовка, ограничением размера тела и ответами только в личных чатах.
- Скрипт настройки меню, команд и webhook.

Telegram-профиль не используется для входа или выбора аккаунта FlowDesk. Автоматической привязки аккаунтов, рассылки рабочих уведомлений в Telegram и создания задач сообщениями боту в этой версии нет. Бот отправляет только подсказку и кнопку запуска. Пароли, сообщения и файлы FlowDesk не пересылаются боту.

Внутри Mini App вход через Google скрыт. Используйте логин и пароль FlowDesk; Google OAuth по-прежнему доступен на сайте в обычном браузере. Если владелец создал вам пользователя, используйте выданные им данные.

## Настройка

1. Откройте [BotFather](https://t.me/BotFather) в Telegram, отправьте `/newbot`, задайте имя и уникальный username. Полученный токен не публикуйте в GitHub и не присылайте в чат.
2. Создайте случайный webhook-секрет у себя в терминале:

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

3. В Vercel → проект FlowDesk → Settings → Environment Variables добавьте три **серверные** переменные для Production:

   ```dotenv
   FLOWDESK_PUBLIC_URL=https://flowdesk-alpha-teal.vercel.app
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   TELEGRAM_WEBHOOK_SECRET=случайный_секрет_из_шага_2
   ```

   Без `NEXT_PUBLIC_`. В `FLOWDESK_PUBLIC_URL` должен быть только HTTPS-адрес сайта, без `/telegram`, параметров и логина/пароля.

4. Отправьте обновлённый код в GitHub и дождитесь Vercel Ready. После изменения переменных окружения также нужен Redeploy.
5. В локальной папке проекта добавьте те же три значения в свой `.env`. Для следующей команды используйте Node.js 22 или новее:

   ```bash
   npm ci
   npm run telegram:setup -- --dry-run
   npm run telegram:setup
   ```

   Первая команда настройки только проверяет конфигурацию. Вторая сначала проверяет опубликованный webhook без отправки сообщения, затем обращается к Telegram и устанавливает команды, кнопку меню и webhook. Уже ожидающие обновления не удаляются.

6. Откройте своего бота и отправьте `/start`. Нажмите **«Открыть FlowDesk»**, войдите и выберите отдел.

В BotFather можно дополнительно задать Main Mini App на адрес `https://flowdesk-alpha-teal.vercel.app/telegram`, чтобы показывать кнопку запуска в профиле бота. Для обычной кнопки меню достаточно скрипта настройки. Если адрес сайта изменится, обновите переменные в Vercel и `.env`, выполните Redeploy и повторите `telegram:setup`.

Новая миграция для Telegram не требуется. Если обновление «Мой день» ещё не установлено, отдельно примените `0013_my_day.sql` по [MY_DAY.md](MY_DAY.md).

## Проверка

- Обычный сайт не должен запрашивать Telegram SDK.
- В Mini App должны работать парольный вход, выбор отдела и переходы к задачам.
- Кнопка Telegram «Назад» возвращает к «Моему дню» отдела, оттуда — к выбору отделов. При открытом диалоге сначала закрывается диалог.
- Верхние и нижние контролы Telegram не закрывают элементы приложения.
- Созданные в Mini App карточки видны на сайте под тем же аккаунтом.
- Запрос к webhook без правильного секрета получает 401, если бот настроен. Без серверной конфигурации — 503.

Не включайте серверный аккаунт Supabase service role для доступа Mini App: пользовательские операции используют прежнюю сессию и RLS. Telegram-параметры не предоставляют никаких дополнительных прав.

Webhook отвечает Telegram непосредственно при команде. При повторной доставке одного обновления приветствие может повториться; рабочие данные бот не меняет.
