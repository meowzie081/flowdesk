# Архитектура и безопасность

## Компоненты

| Компонент | Ответственность |
|---|---|
| Next.js App Router, React, TypeScript | Страницы, формы, клиентская логика и серверные API |
| Tailwind CSS и CSS-переменные | Адаптивная компоновка и две темы |
| Supabase Auth | Сессии, пароли и Google OAuth |
| PostgreSQL и RLS | Данные, связи, роли, ограничения и изоляция отделов |
| Supabase Storage | Приватные файлы с проверкой доступа |
| Supabase Realtime | Обновления сообщений и уведомлений |
| Серверный AI API | Контекст из БД, маскирование, вызов Gemini/Groq/Ollama |
| GA4 | Фиксированные события использования после согласия |
| Docker web и scheduler | Веб-процесс и независимая генерация повторяющихся задач |
| GitHub Actions, SSH, Caddy | Проверки, доставка релизов и HTTPS |

Основные связи: отдел содержит доски; доска содержит колонки и задачи; задача связана с исполнителем, чек-листом, комментариями, файлами и зависимостями. Сообщения принадлежат отделу и могут связываться с карточкой. Членство связывает профиль с отделом и ролью. SQL-миграции находятся в `supabase/migrations`.

## Основные потоки

1. Клиент использует Supabase с пользовательской сессией. PostgreSQL применяет RLS независимо от видимости кнопок.
2. Привилегированные операции создания/сброса пароля проходят серверную проверку владельца. Service role key используется только на сервере.
3. `/api/ai` проверяет сессию и роль, получает доступный контекст, маскирует email/телефоны/секреты и вызывает провайдера. Маскирование эвристическое, не является гарантией удаления любых персональных данных.
4. Файлы находятся в приватных buckets. Приложение выдаёт временные ссылки и безопасный предпросмотр ограниченных форматов.
5. Scheduler с серверным ключом вызывает RPC; блокировки и уникальность защищают от повторной генерации на одну дату.
6. GA4 получает только разрешённые имена событий и категориальные значения. Пути отделов преобразуются в фиксированные названия разделов.

## Проверки безопасности

В проекте есть тесты API управляемых аккаунтов и паролей, изоляции RLS, блокировки со старой сессией, недоступности чужих файлов, неизменяемости журнала, запрета циклических зависимостей, безопасного предпросмотра и границы GA4-параметров. Они покрывают конкретные сценарии, а не заменяют независимый аудит.

## Известные ограничения

- Резервный опрос чата и доски остаётся источником запросов при сбоях Realtime.
- Календарь загружает задачи видимой сетки; очень большие объёмы требуют отдельного замера и оптимизации.
- Рабочие Auth/OAuth/Storage/Realtime и доступность AI-провайдера проверяются на целевом окружении.
- `/api/health` не проверяет все внешние зависимости.
- Откат приложения не отменяет SQL-миграции и не восстанавливает пользовательские данные.
- PWA показывает offline-страницу, полноценного редактирования без сети нет.
- Формальная нагрузочная проверка и независимый пентест не проводились.
