# FlowDesk: идея и требования

Документ оформлен при подготовке существующего приложения к защите. Он систематизирует текущую реализацию и не выдаётся за исходное согласованное с преподавателем ТЗ.

## Идея

Рабочее пространство небольшой команды: задачи на канбане, обсуждения и файлы в одном отделе. AI помогает превратить обсуждение в черновики задач и подготовить сводку, а человек подтверждает создание карточек.

Проблема как проектная гипотеза: договорённости теряются в переписке, сроки и исполнители находятся отдельно, руководителю приходится вручную собирать статус. Пользовательские интервью и измерение экономии времени не проводились; утверждать доказанный бизнес-эффект нельзя.

Роли: владелец отдела, участник, наблюдатель. Граница доступа проходит по членству в отделе. Блокировка относится к конкретному отделу.

## Краткое сравнение ориентиров

Обзор подготовлен с AI при финализации, по официальным страницам на 15.10.2026. Это функциональное сравнение, без тарифных утверждений и без тестирования чужих продуктов.

| Ориентир | Что подтверждено официальными материалами | Решение для FlowDesk |
|---|---|---|
| Trello | Доски, списки, карточки, автоматизация | Канбан как основной рабочий экран; шаблоны и повторы |
| Asana | Представления задач, календарь и зависимости | Отдельный календарь сроков и запрет завершения до готовности предшественников |

FlowDesk делает акцент на связи сообщения и карточки, изоляции отделов и подтверждении AI-черновиков. Уникальность относительно всего рынка не заявляется.

Источники: https://trello.com/en/tour ; https://support.atlassian.com/trello/docs/automation-overview/ ; https://asana.com/features/project-management

## User Stories и критерии приёмки

| ID | История | Проверяемый результат |
|---|---|---|
| US-01 | Как сотрудник, хочу войти в систему | Валидный аккаунт открывает отделы; неверный пароль показывает ошибку |
| US-02 | Как владелец, хочу создать пользователя | Создаётся аккаунт с логином/паролем и ролью в моём отделе; участник не может вызвать операцию |
| US-03 | Как участник, хочу управлять задачами | Создание, редактирование, исполнитель, срок, приоритет, перемещение и архив сохраняются |
| US-04 | Как сотрудник, хочу обсуждать работу | Сообщения, ответы, упоминания и вложения доступны только в моём отделе |
| US-05 | Как участник, хочу создать задачу из обсуждения | Карточка ссылается на сообщение; повторное нажатие не создаёт дубликат на той же доске |
| US-06 | Как сотрудник, хочу видеть сроки | Календарь начинается с понедельника, содержит только необходимые недели и фильтрует задачи |
| US-07 | Как сотрудник, хочу находить информацию | Поиск находит доступные задачи, сообщения и файлы; чужие отделы не раскрываются |
| US-08 | Как участник, хочу подсказки AI | Ответ основан на доступном контексте; создание предложенных карточек требует подтверждения |
| US-09 | Как владелец, хочу ограничить доступ | После блокировки прежняя сессия теряет доступ к данным отдела |
| US-10 | Как участник, хочу повторяющиеся задачи | Scheduler создаёт карточки по расписанию без дубликата на одну дату |
| US-11 | Как пользователь, хочу управлять аналитикой | До согласия нет Google tag; отказ прекращает отправку; содержимое работы не передаётся |
| US-12 | Как разработчик, хочу проверяемую публикацию | PR запускает проверки; production-деплой запускается только после успешного check в main |

## Соответствие учебным требованиям

Есть: более трёх экранов, формы, состояния ошибок/загрузки, адаптивность, CRUD, аутентификация, валидация, PostgreSQL со связанными таблицами, файлы и поиск. Дополнительно: Google OAuth, API AI-провайдеров, GA4-интеграция.

Требуют внешней настройки и проверки: реальный GitHub, публичный HTTPS URL, прохождение GitHub Actions на репозитории, GA4 Realtime и рабочие Supabase Auth/Storage/Realtime. Платежей и email/push-рассылок нет; уведомления внутри приложения реализованы.
